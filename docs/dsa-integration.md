## 页面使用

1. **个股分析**：无需先选股票即可展开“浏览 Skill”，查看 15 个内置框架、适用行情与完整定义。选择快速/标准/完整模式，可附加最多 3 个研究 Skill，或选择自动框架。报告归档后带上研究产物、输入质量和阶段轨迹，重新分析会保留 Skill 选择。
2. **驾驶舱 → 研究与决策信号**：输入带交易所后缀的代码（如 `000001.SZ`），一次最多 20 个；查看信号、研究证据、归档报告、运行记录；手动标记待复评、归档或计算 5 根后续日线观察收益。
3. **定时研究**：默认关闭，保存标的、模式及北京时间后启用。每天最多触发一批，最早 15:35；标的当日日线未就绪或已有活跃批次则等待。当天重启不会重复触发已领取批次。运行时间过去后启动应用，会在当天下一次检查补触发。中断和失败不会自动付费重跑。
4. **模拟盘组合风险**：展开后按需加载已有账户。缺失价格不会用成本伪装行情；总资产和仓位显示不可计算，保留可计算的其他风险。
5. **设置 → 监控 → 更多通知渠道**：保存新渠道配置后，在监控规则选择渠道。空输入保留凭据，“清除配置”删除该渠道配置。接口只返回已配置状态，不回显 Token/URL/会话 ID。

批量与定时研究也提供相同的 Skill 目录。三处选择各自独立；定时选择在点击保存后生效，单次批量选择随本次任务归档。内置目录包括默认多头趋势、均线金叉、放量突破、缩量回踩、底部放量、缠论、波浪理论、龙头策略、热点题材、情绪周期、事件驱动、预期重估、成长质量、箱体震荡、一阳夹三阴。

15 份 YAML 已与固定 DSA commit 逐字节核对；`backend/app/research_skills/upstream.json` 保存来源与校验值，测试同时验证完整文件集合和元数据不被加载器丢弃。默认激活、优先级、适用行情、核心规则编号、工具依赖和调用限制全部保留。自动选择遵守调用限制并使用目录默认值；适用行情与工具字段的同步不代表完整 DSA 路由和工具执行引擎已完成。

当前没有启用用户的定时研究，没有为验证发起真实 LLM 分析或向外部聊天发送消息。适配器测试全部使用模拟响应。

## 契约与兼容

- 新路由通过真实后端扩展注册接入（L2）；个股分析流、驾驶舱和调度器需要改变核心数据流，采用局部源码接线（L3），没有复制现有页面或 provider 仓库。
- 本地新建 `data/user_data/research.sqlite3`，用于任务、批次、信号和定时配置；旧报告和旧偏好不做批量迁移。研究模型带 `schema_version=1`。
- 研究流新增 `run/context/artifact` 事件，`done` 携带服务端归档报告。新前端不再重复保存同一报告，仍兼容旧服务端的 `done` 归档路径。没有终止事件的断流显示失败并保留已收文本。
- 手动与批次共用最多 3 个同时执行的研究任务；每批逐个标的执行；Skill 每次最多 3 个，默认并行 2 个；AI 阶段限时 90 秒。容量不足会明确失败，不形成无界等待队列。
- `succeeded` 表示运行完成，不保证结论质量。正文结构化解析失败、证据不足和输入缺口仍会显示在产物质量中，信号进入待复评。
- 研究评分与输入完整度分开显示；缺证据不制造零分、方向或盈利概率。新闻未来日期同时从提示词与质量统计排除。新闻与财务新鲜度未证实则明确标为未知。
- 后验计算使用同次读取中的同口径复权收盘价，从信号日或之前最近收盘到信号后第 N 根日线；北京时间 15:30 前不把当天日线当完成观察。该数值是观察收益，不是可成交收益或回测结果。
- 信号修改使用版本比较；旧版本返回 409，前端刷新记录。单条变更只失效研究查询键，不清空行情缓存。
- 组合风险使用不复权收盘价与持仓成本，净值回撤来自历史定版记录。页面按需加载，不进入实时行情循环。
- 新通知渠道共用原有后台线程池，限制待执行数量、网络重试和短时重复；投递记录不保存凭据、消息正文和原始异常。当前去重仅在进程内，尚非持久化发件箱。
- `secrets_store` 的合并写与清除增加进程锁，防止并发保存新渠道和其他凭据时覆盖数据。单机多进程写凭据不在此锁的保证范围内。
- 后端关闭时取消批量研究；重启把未完成研究标为中断，不假装成功。研究列表当前展示最近 200 条；没有历史分页或保留期清理工具。

## 达到自动驾驶仍需完成的闭环

当前定时研究只完成“定时 → 确认交易日及标的当日日线存在 → 批次 → Agent → 报告/信号归档”。日线存在不等于全部上游数据质量合格。仍需把以下内容接到统一可追踪的事件链：

1. 同步完成与数据质量门控，按盘前、盘中、盘后节点触发，统一交易日历与缺数据策略。
2. 新证据到达后的自动复评、信号替代关系、组合风险变化、观察窗口成熟后的自动评估和回写。
3. 持久化通知发件箱、跨重启幂等、重试/补偿、失败处理和任务恢复。
4. LLM 调用预算与用量追踪、模型降级、研究质量评估；已有并发上限不能替代成本治理。
5. 其余行情、情报、搜索、券商、Bot 和多市场适配，并按真实凭据和标准数据契约分别验收。

升级时重点复核 `stock_analyzer.py`、`daily_pipeline.py`、`main.py`、`quote_service.py`、前端 `api.ts`、`queryKeys.ts` 与驾驶舱。关闭定时配置即可停止后续自动批次；回退代码时保留新增数据库和凭据文件，不删除用户研究记录。旧 Markdown 报告继续可读。
